# Speedrun: finishing the game end to end (2026-11-02)

A script plays World of Xeen from **Start a New Game** to all three endings
(Clouds, Darkside, World), on the PC (host stub) and on the PocketBook. The
goal is a real win you can watch on the reader, not a tour of the ending
scenes. This was a discovery run: bugs are listed here, not fixed, except
where they blocked the run.

## Findings

P1 = blocks play or loses progress, P2 = fix next, P3 = when convenient.

| # | Prio | What goes wrong | Seen on |
|---|------|-----------------|---------|
| 1 | P1 | The save dialog after the Darkside ending is invisible | host |
| 2 | P2 | Keys don't get past the Dragon Pharaoh's "Press a Key!" pages | host |
| 3 | P2 | Quitting during the Clouds congratulations screen hangs | host |
| 4 | P2 | Crash (SIGFPE) while drawing the debugger console | host |

### 1. Invisible save dialog after the Darkside ending (P1)
After the two score pages, the game opens ScummVM's save dialog
(`showDarkSideScore` → `saves.saveGame()`). The dialog does run, but the
screen keeps showing the Pharaoh's "Press a Key!" page. A player sees a frozen
picture and will probably leave without saving the finished game. After the
Clouds ending the same dialog does show.

### 2. Keys ignored on the Pharaoh pages (P2)
`showPharaohEndTextInner` (Darkside score, start of the World ending): Space
and Enter do nothing or need several presses; a tap works at once. Players tap,
so this mostly affects the keypad's keys and scripts.

### 3. Quit hangs on the Clouds congratulations screen (P2)
`showCloudsEnding4` (clouds_cutscenes.cpp ~962) waits for a key or click and
never checks `shouldQuit()`. On the reader, Home or auto power-off would leave
an app that won't close until the screen is tapped.

### 4. Crash in the debugger console's scrollbar (P2)
Happens now and then right after a debugger `map` command. The console's
scrollbar gets drawn only 2 px high, its corner radius goes negative (-2), and
the theme renderer divides by zero (`VectorRendererSpec.cpp:3299`, via
`ScrollBarWidget::drawWidget`). It's in upstream ScummVM theme code, triggered
by our screen size. Players only reach it through the debugger. The runner
retries a segment that crashes this way.

### 5. Title menu drops a key (P3)
On a fresh start the first key opens the menu, the second is ignored, the
third works. The route presses S three times, 3 s apart.

### 6. Debugger commands lost when typed fast (P3, tooling)
Commands typed under ~1 s apart can vanish and leave the console open. The
route waits 1.5 s between them.

### 7. Script keys didn't reach the debugger on the reader (fixed, 492765d)
The reader's firmware passes only 16 bits of an event's parameters, so the
ASCII code the script packed in got lost and the console ignored every key.
The app now works out the ASCII from the keycode. While a script is driving,
it also keeps the reader's own keyboard closed, because that keyboard covered
the console and sent Escape when dismissed.

## How to run

```
tools/speedrun.py print                       # list every step
tools/speedrun.py host OUT [--from darkside]  # PC, ~25 min, frames in OUT/
tools/speedrun.py device OUT --agent 192.168.178.198:8628
```

For the reader:
- Build and deploy the current build: `pbtk deploy --wifi --restart --build`
  (the reader must be awake with mmIV open).
- The run uses its own save folder (`mmiv/savedir` = `speedrun`) and puts back
  `saves` and `scummvm.ini` when it ends.
- If a run is killed halfway, restore them by hand: set `mmiv/savedir` to
  `saves` and copy `OUT/scummvm.ini.player` back. The player's backup is in
  `~/games/xeen/backup-2026-11-02`.

## The route

The debugger supplies invincibility, strong attacks (`strength`) and
teleports (`map`). Every quest step itself is the game's own script. The route
was worked out from the map scripts with `tools/xeen-events.py` and Stephen S.
Lee's Clouds FAQ.

| Step | Where | What happens |
|---|---|---|
| Xeen Slayer Sword | Vertigo mirror (map 28, 14,10, facing W) | type `i lost it` |
| Equip it | Arturius | remove sabre and shield (the sword is two-handed) |
| Lord Xeen | Xeen's Castle 4 (map 78, 6,9, facing W) | only the sword hurts him; drops **Xeen's Scepter** |
| **Clouds ending** | Sixth Mirror (4,9, facing W) | scepter, then Yes |
| Soul Box | Darkside map 37 (10,14, facing E) | F1 takes it |
| Stasis field | map 87 console (2,8, facing W) | type `where no man has gone before` |
| Corak | map 87 (4,8, facing W), talk three times | takes the Soul Box |
| Dragon Pharaoh | map 86 (6,9, facing W), talk twice | gives the Sleepers' award |
| Four Sleepers | maps 25-28 | each gives an award |
| **Darkside ending** | Sheltem's throne (map 51, 2,13, facing N) | needs Corak's Soul Box |
| **World ending** | Great Pyramid (map 129, 13,15) | needs both endings' items and the four awards |

After the Clouds and Darkside endings the game saves and returns to the title
menu. The run saves checkpoints there (slots 42 and 43) and continues from
them.

## Engine notes

- `intangible` only turns it on; use `intangible off` to turn it off. With it
  on, the party walks through the Sixth Mirror and misses the event.
- The Darkside ending gives the World ending's item before its cutscene, so a
  save made during that ending keeps it.
