# Finishing the game end to end — 2026-11-02

Discovery only, like `device-test-2026-11-02.md`: a scripted playthrough from
**Start a New Game** to all three endings (Clouds, Darkside, World), first
on the host stub, then on the reader. No fixes were made; this file lists what
the run found and how the route works.

## The route

`tools/speedrun.py` holds it; `tools/speedrun.py print` lists every command.
It was worked out from the game's own map scripts with `tools/xeen-events.py`
(it decodes `maze*.evt` / `.mob` straight from `xeen.cc` and `dark.cc`), plus
Stephen S. Lee's Clouds FAQ for the Xeen Slayer Sword. The engine debugger
supplies invincibility, strong attacks (`strength`) and teleports (`map`).
Every quest step is the game's own script.

| Step | Where | What the script needs |
|---|---|---|
| Xeen Slayer Sword | Vertigo mirror (map 28, 14,10, facing W) | answer `i lost it` (mirror entry 59, scripts.cpp `cmdConfirmWord`) |
| equip it | Arturius: remove sabre (W1) and shield (A2), equip W2 | the sword is two-handed |
| Lord Xeen | Xeen's Castle 4 (map 78), stand at 6,9 facing W | immune to everything else; with the sword `strength` kills him in one round; he drops **Xeen's Scepter** (item 90) |
| Clouds ending | Sixth Mirror, 4,9 facing W | scepter, then Yes |
| Soul Box | Darkside map 37, 10,14 facing E | "who will take?" F1 |
| stasis field | map 87 console, 2,8 facing W | answer `where no man has gone before` |
| Corak | map 87, 4,8 facing W, talk three times | gives flag 169, then takes the Soul Box and gives **Soul Box with Corak** (item 160) |
| Dragon Pharaoh | map 86, 6,9 facing W, talk twice | flag 169 gives award 45 |
| four Sleepers | maps 25-28 at 3,12 / 12,12 / 12,3 / 3,3 | award 45 gives awards 61-64 |
| Darkside ending | Sheltem's throne, map 51, 2,13 facing N | item 160 |
| World ending | Great Pyramid, map 129, 13,15 | items 90 and 135 (set by the Darkside ending), awards 61-64 |

After the Clouds and Darkside endings the game shows the score, opens a save
dialog and returns to the title menu. The party keeps playing from that save
(the Darkside one puts it in Castleview). The run saves checkpoints 42 and 43
there and resumes from them.

## How to run it

```
tools/speedrun.py host OUT                 # three host runs, ~25 min, frames in OUT/*/
tools/speedrun.py device OUT [--agent IP:PORT]
```

On the reader it needs a build with the dev event (`pb-platform.h`,
`kDevEvent`): pbtk's agent sends `event 28013 OP ARG` to open the debugger,
press keys and save a checkpoint; only a client with the agent token can.
It sets `mmiv/savedir` to `speedrun` (so it starts at the title menu and never
touches the player's saves), copies `scummvm.ini` aside first and puts it back
afterwards (the endings write `game_won` there), and pings every 15 s so the
reader does not power off.

## Findings

**P1: blocks play or loses progress. P2: next. P3: when convenient.**

1. **P1: the save dialog after the Darkside ending is invisible.** After the
   two score pages, `showDarkSideScore` calls `saves.saveGame()`; ScummVM's
   save chooser runs (backtrace: `SaveLoadChooserSimple::runIntern`, keys go
   "to menu") but the panel keeps showing the Dragon Pharaoh's "Press a Key!"
   page. Taps and keys seem to do nothing, so a player is stuck in front of a
   frozen picture and will likely leave without saving the finished game.
   After the Clouds ending the same dialog does show. Host stub; still to be
   seen on the reader.
2. **P2: keys don't get past the Dragon Pharaoh's "Press a Key!" pages**
   (`showPharaohEndTextInner`: Darkside score, World ending start). Space and
   Enter were ignored, or needed several presses; a tap works at once. On the
   reader a player taps, so this matters for the touch keypad's keys and for
   scripts.
3. **P2: quitting during the Clouds congratulations screen hangs.**
   `showCloudsEnding4` (clouds_cutscenes.cpp ~962) loops until a key or click
   and never checks `shouldQuit()`; the host stub's timeout "quit" left the
   process spinning there. On the reader that is an app that does not close
   (Home, auto power-off) until the screen is tapped.
4. **P3: the title menu drops a press.** On a fresh start (no saves) the first
   key opens the options menu, the second is lost, the third works (S, S, S,
   3 s apart, then A for Adventurer). With two presses the menu just stays.
5. **P2: an intermittent SIGFPE while the debugger console is drawn** (host,
   exit 136). First seen right after `map 78 6 9 0`, then in the full run after
   the first Sleeper's `map`. Backtrace: `ScrollBarWidget::drawWidget` →
   `ThemeEngine::drawScrollbar` (sliderY 50, sliderHeight 308) →
   `drawDD(kDDScrollbarBase)` → `VectorRendererSpec::drawRoundedSquare` →
   `drawBorderRoundedSquareAlgClip` (VectorRendererSpec.cpp:3299) with
   `w=27 h=2 r=-2`: a scrollbar piece only 2 px high gets a negative corner
   radius and divides by zero. Most likely the console as it slides in (its
   height grows from 0), at the e-ink overlay size. Upstream ScummVM theme
   code, triggered by our layout; the player hits it only through the debugger,
   but any scrollbar squeezed to a few pixels would do the same. The runner
   now repeats a segment that dies this way.
6. **P3 (test tooling): debugger commands typed less than ~1 s apart are
   sometimes lost**, leaving the console open; the route waits 1.5 s between
   them.

## Notes on the engine, for later

- Only the Xeen Slayer Sword hurts Lord Xeen (FAQ, and confirmed: nine rounds
  of `strength` attacks without it did nothing).
- `intangible` only turns on; `intangible off` turns it off. With it on, the
  party walks through the Sixth Mirror's wall and misses the event.
- `cmdCutsceneEndDarkside` sets quest item 53 (item 135) before the cutscene,
  so a save made while the save dialog is open keeps it.
